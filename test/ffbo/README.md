### 已确认的三条事实（都经过实测，别再凭直觉改）

1. **光感受器是组胺能（抑制性）**。注入光感受器使其 50 Hz 发放后，视叶内部神经元
   （`ol_intrinsic`，89,403 个）总活动从 9109 Hz 降到 6134 Hz —— **下降 33%**。
   ⇒ 恒定光照只会持续压制下游；**果蝇视觉靠光的变化**（抑制撤除时下游才去抑制发放），
   所以注入必须是**时序图案**而不是稳态光强。
2. **通路是通的**：光以方波通断时，motor 与下行神经元出现**与光周期相位锁定**的响应，
   0.25–4 Hz 全频段 **motor 3.5~5.0σ、DN 2.9~4.5σ**。但幅度只有约 1 个 spike / 815 个 motor（0.1%），
   **足以证明通路成立，远不足以驱动行为**。
3. **测量方法上的两个坑**（都踩过）：
   - 用「相位**均值差**」测方波响应会得到 ≈0 的**假阴性** —— 响应是**瞬态**，必须用**相位折叠**
     （按刺激周期折叠后取各相位均值，再算峰峰/标准误）。
   - 日志每 5 步（100 ms）采样时 Nyquist 只有 5 Hz，2 Hz 以上的响应会被折叠成**假零**；
     做频率响应必须**每步记录**。

### LIF 参数（已验证）

```
dt = 20 ms   tau = 100 ms   V_th = 1.0   复位到 0（不是减阈值！）
I_bg = m·V_th/tau          ⇒ 静息 v_ss = tau·I_bg = m·V_th
```
- **复位必须到 0**：旧代码用「减阈值复位」`v = nv - th`，强驱动下 v 无界累积
  （实测峰值 **v=16.6**），一批神经元因此**粘死满发**，感官输入被完全淹没。
- **dt 用 20 ms**：τ=100 ms 的 LIF 用 1 ms 步长既无必要，又让每步全量遍历 2558 万条边贵 20 倍。
  实测 20 ms 下（全量遍历、CPU、多线程）**1.3~1.5 倍实时**。
- 静息工作点存在**清晰相变**：`m=0.85` 时下游全静默（峰值 v=0.896），`m≈0.9` 时整网点火。

## 🔬 测量方法学（血泪教训，六条缺一不可，2026-09-16）

本会话一共抓到 **6 个假信号**，每一个都是靠对照和交叉验证抓出来的。往后做任何
「刺激 → 神经活动」的测量，必须同时满足：

1. **逐神经元分布**，不能只看群体均值。
   聚合指标的显著性会被几百个细胞各自 0.003 的一致微小偏移虚高（实测「motor 10σ」是假的）。
2. **交叉验证**（前半估权重 `w=Δμ/σ²`、后半评估，再反向一次）。
   样本内 d′ 毫无意义：打乱标签时它也能到 202.9。
3. **等长相位窗口**。
   80/20 这种不平衡会让网络自身的慢漂移在两个字相位上产生系统性差别 ——
   `mcns_net` 里那个 motor d′=63 就是这么来的：把注入幅度改成 0，数字一模一样（60.9/65.9）。
4. **对照必须是「刺激幅度 0」，不是「打乱标签」**。
   打乱恰好把占空比变成 50/50，**把它要暴露的那个不平衡本身消掉了**，于是对照看起来只有 3.0、
   「真效应大 20 倍」——很有欺骗性。
5. **窗口要包含刺激的过渡过程**。
   取两个准静态端点做对比时下游完全测不到；网络响应的是变化的「过程」而不是「状态」。
6. **丢弃升温段**（至少前 2 s）。
   网络有 0~0.5 s 的升温瞬态，刺激若从 t=0 开始，整段升温会落进单一相位，造出 d′=-15 的假象。
   另外低通读出的时间序列有强自相关，直接算 d′ 也会虚高，应当用相位折叠。

配套的坑：日志采样间隔限制折叠分辨率（每 5 步=100ms 采样时 Nyquist 5Hz，2Hz 以上被折叠成假零，
做频率响应必须每步记录）；相位标签不能一律按「平均亮度」判（loom 的暗盘只占视野一小块，
平均亮度几乎恒定，标签会失效）。

## ⚠ 诊断纪律补充（第 7 条）：周期性标签会与网络自身振荡锁相

`--pattern reverse`（方向标签 = 漂移方向）实测**不成立**，幅度 0 对照直接否掉：

| | 注入 80 | 注入 0（对照） |
|---|---|---|
| ol_intrinsic d′ | 304.1 | **304.0** |
| visual_projection d′ | 97.9 | 97.9 |
| vnc_intrinsic d′ | 115.4 | 115.4 |

数字逐位相同 ⇒ 那个 d′≈300 与刺激无关。原因是 `rdir` 按**固定周期**翻转
（每 `1/stripe_hz` 秒一次），而网络在固定种子 + 固定噪声表下是**确定性动力系统**，
自身有一条周期与之可通约的振荡；解码器（含交叉验证）把这条振荡当成了「方向信号」，
两半自然一致，所以交叉验证也验不出来。

**规则**：凡是「相位/方向/状态」类标签，触发时刻必须是**随机化**的（随机块长），
不能让标签与任何固定周期绑定；并且**幅度 0 对照必须与实验同参数跑**。
同源假象在这个项目里已经出现过三次：聚合 10σ、占空比不平衡、标签周期锁相。

**在修好标签随机化之前，任何方向选择性/运动选择性结论都不可用**——
包括 r501 里「T4/T5 是亮度检测器而非运动检测器」这条，其判据（运动光栅 d′ 1.2 对对照 −0.3）
需要重新验证。

## ⚠ 诊断纪律补充（第 10 条）：改了 xhqm 的头文件必须全量重编 —— build 里没有 header depfile

实测陷阱（r548 修阴影 pass 尺寸开关时踩到，症状极隐蔽）：

- `xhqm/build` 是 CMake + Ninja，但**没有 `/showIncludes` 依赖**，`ninja -t deps` 里
  查不到任何 `.h`。于是改头文件**不会**触发包含它的 `.cpp` 重编。
- 后果不是「改动没生效」这么简单，而是**同一个 DLL 里两批目标文件对同一个类有不同布局**：
  新编的那批按新布局访问成员，旧的那批（如 `fantasy/property.cpp`）按旧布局构造对象
  ⇒ 构造出来的对象里，**插入点之后的成员全是垃圾值**。
- 现场表现：`theory_shadow` 的 `m_size` 正常（2048），而插在它后面的 `m_applied` /
  `m_enabled` / `m_light_env` 读到 `745829633` / `0` / `0xDD6E...`（垃圾）。
  因为 `m_enabled` 恰好读成 0，阴影 pass 直接 early-return ⇒ **阴影悄悄消失**，
  而图像「看起来还行」，只有拿 shadow on/off 两张图对哈希才发现两张图完全一样。
- **判据**：改过头文件后，必须 `Remove-Item build\CMakeFiles\xhqm.dir -Recurse -Force`
  再 `ninja xhqm.dll`（全量 90 个 TU，几分钟）。判断是否中招的最快办法就是
  **构造后立刻打印「插在改动位置之后的成员」**，看是否为垃圾。

同源教训：**「改动没效果」和「改动以不可能的方向生效」是两种病**，后者更危险。

## ⚠ 诊断纪律补充（第 11 条）：定位性能问题先量「墙钟 vs 本线程 CPU」

r544 排查「渲染 110ms」时，第一条立住的判据不是任何火焰图，而是
`GetThreadTimes` 给出的**本线程 CPU 时间**：

```
帧图执行 109.9ms（其中本线程 CPU 107.3ms）| 起止帧+呈现 0.3ms
```

CPU ≈ 墙钟 ⇒ 主线程自己在算（不是等 GPU / 不是 vsync / 不是 swapchain）；
CPU ≪ 墙钟 ⇒ 在等外部。这一条当场把整片「GPU 慢 / 驱动慢 / 阻塞」的可能性排除，
避免了几小时的错误方向。同一次排查里另有两条辅助判据：
**逐对象斜率**（`--hide-after K` 的截距=固定开销、斜率=每次绘制开销）与
**逐 pass 计时**（本管线 `declare` 都是空 reads/writes，故按 `fg->passes()` 注册序
直接调 `p->render()` 与拓扑序等价）。

## ⚠ 诊断纪律补充（第 9 条）：HRC 需要【空间基线】，时间非对称不够

`--hrc-wire` 给 T4/T5 接上「快腿 Mi1 + 慢腿 Tm3/Tm9/Tm2（慢电压依赖通道）」之后，
方向选择性依然不出现（T4a +1.7/+2.0 对对照 +0.2/+0.5；T4c/T4d 的对照与信号持平甚至更高）。

原因用离线几何测量（`offline_hrc_geom.py`）查清了 —— **两条腿的平均空间偏移几乎是 0**：

| 类型 | Δaz 中位(°) | 细胞间标准差(°) |
|---|---|---|
| T4a | −0.340 | 5.387 |
| T4b | −0.181 | 5.430 |
| T4c | −0.283 | 5.818 |
| T4d | −0.329 | 5.743 |
| T5a | −0.208 | 5.662 |
| T5b | +0.048 | 5.109 |

方法：把光感受器的实测方位角（光学柱 h1/h2）沿连接组加权平均传播 4 跳，
再对每个 T4/T5 比较其快腿入边与慢腿入边的平均方位角。

**方法自检**（必须先做，否则「没有偏移」这个结论不成立）：传播后每个类型的方位角都覆盖
整个视野（−135° ~ +8.5°，标准差 ~35°），所以传播保留了空间结构、没有退化。
另外每个 T4 约 7 条 Mi1 边 + 6 条 Tm3 边，若各自独立散布 35°、其均值标准误应是 13°，
而实测腿间差的标准差只有 5.5° —— 说明同一 T4 的两组输入各自成簇（柱状接线是对的），
但**两簇的位置平均在同一方位**。

**一致性检查也失败**：T4a（前后向）与 T4d（后前向）的偏移符号应当相反，实测都是负的。

**结论**：在这份连接组里，「一条腿取 Mi1、另一条腿取 Tm3」的做法**没有空间基线**。
而 cellsim 的台架测试早就给出了阴性对照：两条腿用同一个快通道时方向指数**恒等于 0.00**
（r503）—— 时间非对称本身产生不了方向选择性，必须有空间偏移配合（Δt = Δx/v）。

**所以方向选择性要走「显式构造空间基线」**：用真实的光学柱映射给每个 T4 指定
一条来自柱 c 的快腿和一条来自柱 c+Δc 的慢腿，并让漂移速度与之匹配，
而不是指望连接组在中间神经元这一级把偏移提供出来。
这与 fly64 的做法一致（它也是把 HRC 手写成 raw_x/raw_y 规则、直接注入视觉细胞）。

## ⚠ 诊断纪律补充（第 8 条）：群体 d′ 必须先扣掉噪声底，否则它只反映细胞数

原实现 `群体 d′ = sqrt(Σ z²)`，其中 `z = Δ/σ`。**纯噪声下 E[z²]=1**
⇒ `Σz² ≈ N` ⇒ `sqrt(Σz²) ≈ sqrt(N)`，这一项**与刺激无关、只随细胞数增长**。

实测症状：ol_intrinsic 有 89275 个细胞，`sqrt(89275) = 298.8`，而程序给出的正是
**注入 80 得 304.1、注入 0 得 304.0** —— 逐位相同。整个「逐级衰减」表里那些大数字
有一大部分是 `sqrt(N)` 噪声底，跨群体（细胞数不同）根本不可比。

修法：`sqrt(max(0, Σ(z²−1)))`。修好后注入 0 的对照**精确给出 0.0**，注入 80 只让
光感受器给出 880.5。**判据：对照必须塌到 0，否则这个统计量不能用。**

（这一条是被幅度 0 对照逼出来的：对照不改数字 ⇒ 那个数字不含刺激信息。
我先后误判过两次成因——先怀疑占空比不平衡、再怀疑标签周期与网络振荡锁相，
都改掉之后对照依旧是 155 对 149，最后才发现是统计量本身。**先怀疑自己的量，再怀疑实验。**）

## 视觉通路（FAFB 光感受器 → 小眼 → ON/OFF → 视叶）

数据依据（全部实测核对）：

|---|---|---|

## 蘑菇体学习（多巴胺调制可塑性）

这是模型目前**唯一具备学习能力的部分**，实现的正是果蝇嗅觉联想学习的真实机制。

### 数据依据（实测）

| 群体 | 数量 | 作用 |
|---|---|---|
| **KC**（Kenyon 细胞）| 5,177（KCg-m 2189 / KCab 1643 / …）| 气味表征，学习基质 |
| **DAN** | 331（27 种）| 多巴胺信号 |
| ↳ **PAM** 家族 | **307**（PAM01–15）| **奖励**型多巴胺 |
| ↳ **PPL** 家族 | **24**（PPL1xx/2xx）| **惩罚**型多巴胺 |
| **MBON** | 96（35 种）| 蘑菇体输出 |
| ORN | 2,281（**54 个嗅小球**，如 DA1/VA1d/VL1）| 气味输入通道 |
| ALPN | 685 | 嗅觉投射神经元 |

突触连接（实测）：

| 连接 | 突触数 | 对数 |
|---|---|---|
| **KC → MBON** | 169,931 | **38,915** |
| PAM → MBON / KC | 9,099 / 956 | — |
| PPL → MBON / KC | 3,853 / 873 | — |
| ALPN → KC | 316,862 | — |

注意 DAN 打到 **MBON** 的突触比打到 KC 的多一个量级——DA 同时调制 KC 末梢与 MBON 树突，不是只作用于 KC。

### 学习规则（三因子 Hebb）

```
CS（条件刺激）：气味源 → ORN(嗅小球通道) → ALPN → KC 发放
   ① KC 发放时在其输出突触上留下 eligibility 痕迹（指数衰减，τ≈1s）
US（无条件刺激）：身体状态 → PAM（奖励）/ PPL（惩罚）
   ② 痕迹与多巴胺信号在时间上重合时改权重：
        plastic += lr × (reward − punish) × trace
        实际权重 w = base × (1 + plastic)，plastic 被限制在 [0, +3.0]
   ③ 同源性衰减（plastic 缓慢回零，防饱和）
```

CS 是场景里的实体物件：`fruitfly.xml` 的 `odor_source`（球体，位于头部前方 0.12 m）。
气味浓度按「触角到气味源的方向 × 距离衰减」算，驱动一个嗅小球通道的 ORN。

### 实测结果（证明选择性可塑在起作用）

```
可塑突触: KC→MBON 21,438 条（脑网络 CSR 内的对应边）
可塑权重: n=21438  已改动=2456 (11.5%)  均=+0.344  标准差=0.956  范围=[0.000 +3.000]
更新次数: 3,115,073（训练后期收敛，均值与已改动数不再变化）
```

三条证据说明这是**选择性**学习而非整体漂移：

1. 只有 **11.5%** 的突触被改动——正是气味激活过的那些 KC（留下痕迹）的输出突触
2. **标准差 0.956**，分布确实分化开了，不是均匀抬高
3. 范围在 +3.0 处截断（`w_max`），均值与改动数随训练**收敛**，无发散

### 坐标系的坑（两次踩同一个）

气味方向判断最初恒为 0，根因是**用了错误的局部轴当「前方」**：
head 的局部 **x 是左右轴**、**局部 y 才是前后轴**（喙 rostrum 在局部 `y=+0.0368`）。
用局部 x 算出的 align 与前进方向垂直、恒为 0。MuJoCo 的 `xmat` 按**列**存局部轴在世界系中的
方向：列0=x、列1=y、列2=z。符号按世界 x 分量自适应用 `+y` 侧。

> 同一个「轴向/符号」问题在这个项目里出现过多次（复眼朝向、气味朝向、相机跟随）。
> 判据永远是：**用两个已知不同位置的部件做差**去反推轴，不要凭直觉。

  产生奖惩的任务（例如气味咬合身体状态，或让气味源移动产生时间结构）。
- **学习结果还没接进行为**：MBON 的活动已记录（`mbon_readout`）但未接到下行/运动。
  24 个头颈运动神经元（`MN-NTct-neck` 等）可用于转向读出。

## 让它动起来（步态 + 推进）

此前果蝇只能站立：腿部 ctrl 被肌肉级映射压到 ±0.1 附近，只有微小摆动，不迈步。

### 步态（中央模式发生器）

给 motor 组的输入叠加节律振荡，**相位由「侧别 + 节段」决定**：

```
同侧前腿(T1)与后腿(T3) 同相，中腿(T2) 反相  ← 这就是果蝇的三角步态
左右两侧相差半周期（反相）
θ = 2π · f · t + phase(side, segment)，默认 f = 2 Hz
```

侧别取自 motor 组的 `Soma side`（同肌肉左右各自成组，所以侧别天然可分）。

### 推进

只用步态不够——足部摩擦产生不了可靠位移（实测会朝后漂移），而**直接改 `qvel` 会被 `mj_step`
的积分覆盖**。正解是**施加外力**（物理上等于主动蹬地），并用速度闭环调力的大小：

```
v_fwd = qvel · 前向 ;  dv = v_target − v_fwd ;  F = clamp(dv × 4000, ±3000)
xfrc_applied[thorax] = F × 前向（只推水平分量，不推垂直，避免影响站立）
```

### 实测

启停对照：关闭推进时 32 秒仅漂移 2.6 cm；开启后同时间走到 **18.7 cm**，并可持续到 67 cm。
**z 始终稳定在 0.127~0.140**——说明是「走」而不是摔倒滑行。

> **已知未解决（方向不可控）**：位移方向**不由推进力决定**。诊断过程：
> 1. `--fwd-sign` 取 ±1 时位移都朝 -x；+1 时速度冲到 **2.08 m/s**（目标 0.06，推力大了约 40 倍）
>    → 增益从 kf=4000/上限3000 降到 kf=60/上限120，再取中间 kf=500/上限800
> 2. 降增益后位移量级正常，方向仍朝 -x。**把推进力完全关掉（`--fwd 0`）后，
>    仅步态在 30 秒内仍漂移 -0.32 m** → 根因是**步态自身的 -x 偏置**：
>    它是振荡经摩擦/重心不对称整流出来的，量级压过外力
> 3. 试过给步态整体加 π 相位偏移：幅度 -0.32 → -0.23，**但方向不变**，
>    说明该偏置不是简单相位能翻转的
>
> 4. **再缩小步态幅度后（amp 40→12、步频 2→6Hz）偏置从 -0.32 降到 -0.043**，
>    于是有条件做干净对照（排除步态偏置干扰）：
>      `--fwd-sign +1` → 前向向量 (-1.00) → dx = -0.025
>      `--fwd-sign -1` → 前向向量 (+1.00) → dx = -0.024
>    **前向向量正确翻转、位移方向却完全相同（只差 0.001）** → 这否定了「符号搞反」，
>    说明 **`xfrc_applied` 对质心位移没有产生可观测影响**，是更根本的问题。
>    怀疑：力施加在 `g_body_up_body`(thorax) 上，而 freejoint 未必挂在 thorax；
>    需用一个恒定水平力做最小验证，确认 `xfrc_applied` 是否被正确累加到质心。
>
> 5. **用独立探针 `force_probe.cpp` 扫出力-位移关系**（这一步早该做，之前一直在盲调增益）：

| 施加力（向 +x）| 2 秒位移 | v_x |
|---|---|---|
| ≤0.005 N | ≈0 | ~0（被地面静摩擦吃掉）|
| 0.02 N | -9e-5 | 0.0033 |
| 0.05 N | 0.00 | 0.010 |
| **0.20 N** | **+4.7e-4** | 0.043 |
| 1.00 N | +181 | 120（爆炸）|

> 探针同时确认：**freejoint 确实挂在 thorax**(body=1)、**总质量仅 0.000985 kg**。
> 静摩擦阈值在 **0.02~0.05 N**；把力从「远超 1N」降到 0.18N 后，位移从 -0.043 只到 -0.055，
> **步态偏置仍在主导**。
>
> 这里的根本矛盾：**净位移必须克服静摩擦（≥0.02N），而实现目标速度 0.06 m/s 所需的
> 理论力仅 4.5e-5 N —— 差三个量级**。也就是说「慢慢匀速走」在这个模型里做不到：
> 要么力不够、被摩擦锁住；要么力够大就开始窜。后续要么改控制方式（如直接控质心位置
> 而非速度），要么大幅提高步态自身的净推进能力。
>
> 结论：**方向控制目前不可用**，但「会走」稳定可用——默认参数下 30 秒位移约 4cm、
> z 稳定 0.126~0.129。当前默认 amp=12 / 6Hz / `--fwd-sign -1`。

## 转向：机制已通，但指令源仍不是神经活动（未达标）

### 已确认可行的部分

**用左右腿的步态不对称产生转向力矩**，物理上是可行的（实测）：

| 方式 | dy（转向位移）| 备注 |
|---|---|---|
| 仅调左右摆幅差（turn-amp=1.2，小步幅）| 0.002 | 几乎无效 |
| 大幅步态（ctrl≈0.5）+ 摆幅差 | 0.017 | 有转向迹象 |
| 大幅步态 + 左右整体偏置（一侧伸/一侧屈）| 0.018 | 与前者同量级 |

即：**转向需要大幅步态才做得出来**（小步幅的摆动被地面静摩擦吃掉，形不成力矩）。
大幅步态下 z 会到 0.15~0.17（剧烈运动），姿态不如小步幅时稳定。

### 为什么指令源还不是神经活动

目标是「转向由果蝇自己的神经活动决定」，做法是取**左右两侧嗅觉投射神经元 ALPN 的
放电率差**作为转向指令（气味→ORN→ALPN 左/右通路→腿不对称）。但**这一步被数据卡住**：

- `classification.csv` 的 ALPN 共 685 个，坐标来自 `coordinates.csv`
- 但 **ALPN 的解剖 y 坐标无法分左右**：y 范围 113744~364480、中位 246928，
  用「R1-6 已标注左右的 y 中位中点」去划分，得到 左29 / 右656 —— 极度不对称，
  说明 ALPN 大多落在中线附近，y 轴分不开左右
- 因此当前实现里 `g_turn_from_neurons=false`，**回退到用「气味相对头部的侧向分量」
  （外部几何量）作为转向指令**，日志里会明确标出 `来源=几何`

### 要让「神经控制」达标，需要补的东西

按可行性排序：

1. **神经元的形态极性 / 轴突投射方向**（FAFB 有 skeleton 数据，但只下过坐标）——
   有了支配侧才能把任何群体分成左右。这是最通用的解法。
2. **换成左右本身就对称的神经元群体**：例如 T4/T5 这类视叶神经元，
   `visual_neuron_types.csv` 里**带 side 标注**（可直接用）。
   用视觉线索（而非嗅觉）驱动转向，就能立刻做到「神经活动决定转向」。
3. 用连接组拓扑反推支配侧（需要完整突触级数据）。

### 转向指令改为网络内部量（已达标）

原来的思路（取左右 ALPN 放电率差）被数据卡住后，换了个更直接、也更符合语义的来源：
**左/右两侧 motor 神经元的放电率差**。

- motor 组天然带 `Soma side`（同肌肉左右各自成组），是**数据里直接标注的侧别**，
  不需要按坐标推算——绕开了 ALPN 那个限制
- 语义上也更顺：转向本来就是运动侧的事，不必绕到感觉侧再回来
- 反应链：`motor 神经元活动 → 两侧腿不对称 → 转向`，**全部发生在网络内部**，
  不含任何外部几何计算

实测对比（同一份代码，只换指令源）：

| 指令源 | dy（转向）| dx | z 范围 |
|---|---|---|---|
| 几何量（气味侧向）+ 大幅步态 | 0.018 | -0.192 | 0.122~0.170 |
| **神经量（左右 motor 放电率差）+ 大幅步态** | **0.067** | **+0.090** | **0.127~0.134** |

神经驱动下转向位移与前进位移同量级（0.067 vs 0.090），而且姿态更稳（z 不再飘到 0.17）。
日志里会标 `来源=神经` 以便核验。

> 现状：**运动（走 + 转向）已全部由网络内部量驱动**；`xfrc_applied` 那条外部推进路径
> 已弃用（`g_fwd_speed` 默认 0）。要让转向进一步「有意义」（例如朝气味源转），
> 还需要把气味信息通过连接组送进运动侧——目前运动侧的活动来自网络背景与突触噪声。

## 感觉→运动闭环（已接上，「趋近」尚未证实）

在「运动由 motor 活动驱动」的基础上，把**气味侧向**接进了网络：

```
气味在左/右（外界信息）→ vision_system 把它编码成 R1-6 的左右不对称活动
   → 连接组传播 → 运动侧 motor 放电率随之产生左右差
      → 腿的步态不对称 → 转向
```

为什么用 R1-6 当侧向接收器：**ALPN/ORN 的坐标分不了左右**（实测 29/656），
而 R1-6 带 `side` 标注、可靠。这一步只负责把「外界信息」写进网络，
之后的转向仍由 motor 放电率差决定（日志 `来源=神经`）。

### 已确认

- 气味侧向**确实**在 R1-6 上造出左右放电差（日志有 `光感受器放电 左X 右Y 差±Z`）
- 转向指令确实来自 motor 放电率差，不依赖外部几何量
- 姿态稳定（z 0.123~0.133）

### 未确认：「趋近」不成立

side-gain 扫描（气味源固定在左侧 y=+0.10，趋近应 dy>0）：

| side-gain | 左右放电差 | dx / dy | 结果 |
|---|---|---|---|
| 3e4 | +3733 | -0.101 / -0.012 | 回避 |
| 8e4 | +3733 | -0.027 / **+0.031** | 趋近 |
| 2e5 | +688 | -0.057 / **-0.084** | 回避 |

**相邻参数就从"趋近"翻到"回避"**，说明方向是噪声或光感受器饱和在主导，
不是气味在决定。要证实趋近需要：
1. 先让气味信号稳定压过运动侧噪声（校准光感受器工作点、降低噪声增益）
2. 再做左右对照、多次复现

> 一句话：**闭环的"接线"是通的，但还不足以说"它学会了朝气味走"。**

### 肌肉级映射

MANC 的 motor 神经元用 `Sub Class = MN-<神经束>-<肌肉名>` 标注（如 `MN-LegNpT1-Ti_flexor`、
`MN-WTct-DLM_c-f`）。**每块肌肉左右两侧各有一组同名神经元，共 216 组**——必须用 `Soma side`
映射到同侧的 DOF，不能双侧平均（否则左右腿被同一信号驱动、无法行走）。

规则表在 `fly_brain_manc_view.cpp` 的 `g_rules[]`：把「肌肉名 → 该侧 DOF」写成表，再按胸节
（`ProLN→T1`、`MesoLN→T2`、`MetaLN→T3`）与侧别展开成具体 actuator 名。实测 216 组中 141 组接线成功。

DOF ↔ 肌肉对照（每条腿每侧 8 个 DOF）：

| DOF | 驱动肌肉 |
|---|---|
| `coxa_abduct` | Pleural_remotor/abductor、Tergopleural/Pleural_promotor |
| `coxa_twist` | Fe_reductor、Sternal_anterior/posterior_rotator |
| `coxa` | Sternal_adductor |
| `femur_twist` | Tergotr.、Sternotrochanter、TTM |
| `femur` | Tr_flexor、Tr_extensor、Acc._tr_flexor |
| `tibia` | Ti_flexor、Ti_extensor、Acc._ti_flexor |
| `tarsus` / `tarsus2` | Ta_depressor、Ta_levator |
| 翅 `wing_yaw/roll/pitch` | Tergopleural（yaw）、DVM 1~3（roll）、DLM a-b/c-f（pitch） |
| 腹 `abdomen_abduct`/`abdomen` | MN-ANm / MN-multi 的 abdomen、abdomen_A1/A2 |
| 头 `head`/`head_twist`/`head_abduct` | NTct 的 neck、TH1、TH2、AD |

未映射的 29 / 78 个 actuator：8 个 `adhere_*`（黏附器，非肌肉）+ 触角/喙/唇瓣（MANC 未标注那些小肌）。
`ltm`/`ltm1-tibia`/`ltm2-femur` 是爪垫长腱肌，模型里没有对应 DOF。

**ctrl 增益很关键**：`g_motor_gain` 取 30 时，稀疏放电（0~0.05）会让 ctrl 长期被 clamp 到 ±1，
等效恒定驱动、把腿推僵（实测果蝇会慢慢蹲下，z 0.126→0.044）。取 4 后腿部 ctrl 落在 ±0.1、
z 稳定 0.126、xy 漂移 <2 mm。

## 数值约定与踩过的坑

**MANC 的 `Flow` 列是「纤维相对神经索的方向」，不是感觉/运动**：`descending`(1328) 标 afferent，
`ascending`(1862)+`motor`(737) 标 efferent。真正的运动输出层是 `Super Class = motor` 那 737 个
（平均 3464 入 / 56 出突触，纯输出型）；感觉层是 `Super Class = sensory` 的 5925 个。
逐类极性判据：sensory 出/入 = 3.67、motor = 0.02、descending = 7.15（符合生物学）。

**脉冲网络三件事必须一起调**，否则「链路全通但没输出」：

1. 背景电流：`I_bg * tau` 必须明确高于阈值，否则稳态卡在阈值下方，全网络零发放。
2. 阈值异质性：均匀驱动 + 相同阈值 = 全网同帧发放（实测 139k/139k）。逐神经元 `U[0.85,1.15]` 才有分布。
3. 归一化尺度：突触后归一化 + 平均入度摊薄后单条突触仅约 0.001，信号传不过 2~3 跳
   → 改突触前归一化并配显式增益 `g_syn`。当前：`I_bg=88`、`I_in=300`、`g_syn=20`。

**actuator 名不要正则解析 XML，也不要凭猜测**：`fruitfly.xml` 里 101 个 `<general>` 只有 78 个是
actuator（其余是 default 块改属性），正解是 `mj_id2name(m, mjOBJ_ACTUATOR, j)`。
本项目的 78 个是：head=14、wing=6、abdomen=2、legT1/T2/T3=18/18/16、haltere 无、末尾 8 个 `adhere_*`；
**每条腿每侧只有 8 个 DOF**（没有 tarsus3~5），腿名是驼峰式 `coxa_abduct_T1_left`。
用 `actuator_dump.cpp` 导出真实名单再写映射，不要照 XML 文本猜——我照文本猜过一轮，
生成的名字里 `wing_pitch_l`、`haltere_left` 等全部不存在。

**`nerve_tct` 这类解析要按内容找而不是按固定偏移**：神经束名可能是 `LegNpT2.LTct`（带 `.LTct` 后缀），
用固定偏移会取到 `.`，生成 `tibia_T_left`；应取 `LegNpT` 之后的第一个数字。

**ctrl 需要自适应基线**：静息发放率若用固定映射会被压到 ctrl 负端，腿被持续压低、果蝇慢慢下沉
（z 0.147→0.130）。以慢速滑动平均为零位（EMA 0.002）后稳定。增益同理要小：`g_motor_gain=30`
会让稀疏放电下的 ctrl 长期贴边、腿被推僵而蹲下，改用 4。

**MuJoCo 用 ctypes 读结构体极易偏移错位**：我用 `ctypes.Structure` 只声明 `nq/nv/nu` 三个字段去读
`mjModel`，读到的是错位的值（把 `nv` 当成了 `nu`，得出「108 个 actuator」的错误结论）。
要拿模型信息就用 C++ 写个小工具（`actuator_dump.cpp`），别猜结构体布局。

**渲染**：`xhqm_rgba` 是 **BGR 字节序**——`0xffff0000` 渲染出来是蓝色，要用宏不要用字面量。
fantasy 场景默认只有环境光 `0x505050` 且无方向光，物体会是无明暗的剪影；方向光在着色器里除以 π，
环境光需压低（`0x464646`）才出立体感。

**其它**：所有文件是无 BOM UTF-8（`.bat` 例外，必须纯 ASCII，cmd 按 GBK 解析中文注释会报错）；
`models::coord(matrix)` 被 3 参数重载遮蔽，需显式 `system::coord()`；`apply_world` 是左乘叠加，
每帧调用会累积导致散架。
